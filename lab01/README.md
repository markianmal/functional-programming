## 1. Архітектурний підхід та реалізація вимог

1. **Чисте ядро (`core.py`):**
   - Усі функції детерміновані: відсутні виклики `print`, операції вводу/виводу або звернення до системного часу.
   - Відсутній спільний змінюваний глобальний стан.
   - Імутабельність: жодна функція не мутує вхідні словники чи списки (`{**item, ...}` та генератори списків).
2. **Параметризація (`typing.Callable`):**
   - `NeedRestockFn` — предикат відбору позицій.
   - `RestockQtyFn` — розрахунок обсягу поповнення.
   - `DiscountFn` — застосування оптових дисконтів залежно від обсягу/ціни.
   - `TaxFn` — політика оподаткування (ПДВ).
3. **Функція вищого порядку:**
   - `make_restock_processor` повертає сконфігуровану функцію обробки (`Callable[[Iterable[StockItem]], RestockReport]`).
   - Реалізовано функцію математичної композиції `compose(f, g)`.
4. **Ізоляція побічних ефектів (`app.py`):**
   - Форматування звіту винесено в чисту функцію `format_report`.
   - Взаємодія з системним часом інжектується через `get_current_timestamp(time_provider)`.
   - Єдиний `print` виконується на верхньому рівні входу додатка.
