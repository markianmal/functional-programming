## Теоретичний аналіз

### База рекурсії та рекурсивний крок
- **Базовий випадок:** Якщо індекс будь-якого з рядків дорівнює його довжині ($i = |s_1|$ або $j = |s_2|$), спільних символів більше бути не може: `return 0`.
- **Рекурсивний крок:** 
  - Якщо $s_1[i] == s_2[j]$: символ входить у LCS, продовжуємо пошук `1 + rec(i + 1, j + 1)`.
  - Якщо $s_1[i] \neq s_2[j]$: обираємо максимум між пропуском символу першого або другого рядка `max(rec(i + 1, j), rec(i, j + 1))`.

### Ліміт рекурсії CPython та відсутність TCO
1. **Recursion Limit:** CPython встановлює безпековий ліміт глибини викликів (за замовчуванням $\approx 1000$, перевіряється `sys.getrecursionlimit()`). Він потрібен для захисту нативного C-стека процесу від переповнення. Спроба обійти обмеження через `sys.setrecursionlimit()` несе ризик аварійного завершення інтерпретатора (Segmentation Fault).
2. **Відсутність TCO (Tail-Call Optimization):** Творці CPython свідомо не імплементують TCO, щоб зберігати повний і точний stack trace для налагодження та аналізу винятків. Тому навіть tail-рекурсивний код вичерпує ліміт стека.
3. **Ітеративна безпека:** Ітеративна версія з табуляцією (`lcs_iterative`) працює в купі (heap memory) через звичайні списки, має пам'ять $O(\min(n, m))$ і виконується без загрози `RecursionError` незалежно від розміру вхідних даних.
